# 数学论文阅读路由

按用户的当前任务选择模块，保留已提供的目标、来源和文件约束。不要为一个局部问题强制生成整篇论文索引。

## 选择模块

| 用户任务 | 读取模块 | 所需输入 |
| --- | --- | --- |
| 提取结构、陈述或假设 | `skill_base.md` | 原论文全文或相关段落；只提供局部时说明覆盖范围 |
| 画依赖图、安排阅读路径 | `skill_pathway_proof.md` | 已有 JSON 或从目标原文提取的局部实体与依赖 |
| 解释定理、展开证明或分析缺口 | `skill_paper_deep_read.md` | 相关原文；JSON 可辅助定位，不是前提 |
| 查找文献或追溯引用 | `skill_literature_search.md` | 用户问题、已知元数据、原文引文或已有索引 |
| 保存文献和阅读笔记 | `skill_reference_manager.md` | 用户确认的元数据、原文与笔记；不要求完整 JSON |

## 执行与纠错

1. 只加载本次需要的模块。需要组合任务时按实际依赖处理，不预先跑完所有步骤。
2. 用原文核对作者陈述、假设和引用位置。已有 JSON 和报告均是可纠正的工作记录；缺失字段不等于论文没有相应内容。
3. 若用户只问一个定理，直接读取相关段落。若需要图但没有 JSON，建立所需的局部工作索引，并列出尚未提取的范围。
4. 发现提取错误时，依据原文修正当前记录，简要说明位置及改动，更新受影响的报告和图；不需要锁定实体或重走全部阶段。
5. 只有原文确认的内部依赖进入确认图：`B.dependencies` 含 `A` 表示 `A -> B`。不确定和外部依赖分别标记，不能用来增加确认图的度数。
6. 把原文、解释、补充推导和未解决问题分开。原文疑似笔误需保持原句并说明疑点，不以 Agent 猜测替换作者文字。
7. 保存和交接时保留相关来源、未解决问题、用户笔记及实际检查范围。没有访问原文时应说明限制，不把结构化记录称为已核验的数学事实。
